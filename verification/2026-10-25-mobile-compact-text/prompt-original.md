# 모바일 글 양 줄이기: 범례 시트 · 긴 설명 접기 · 첫 화면 대회 문구 숨김 — Claude Code 작업 지침

## 배경

휴대폰(390px)에서 화면마다 읽어야 할 글이 너무 많다. 특히 다음 세 곳이 문제다.

- **탐색 지도**: 지도 아래에 범례 문단, '색의 의미', '지도 읽는 법', '그 밖의 기능'이 차례로 쌓여 있다. 지도를 보려고 들어왔는데 설명 글을 한참 지나야 종 정보에 닿는다.
- **비교와 지표 · 근거와 방법**: '읽는 법'의 긴 목록(밀집 구간 설명 등), 국가 해양생물 시스템 비교 4열 표(MBRIS · 해양생물 공간정보시스템 · 해양바이오뱅크 · 이 지도), 02·03 영역의 긴 문단이 휴대폰에서 모두 펼쳐져 있다.
- **첫 화면**: 'Ocean 20 Challenge · 해양 10대 과제 …' 줄과 '흩어진 자료를 잇고 … 세계해양포럼 … UN Ocean Decade' 줄이 '문제 → 해결 → 바다 탐색하기' 흐름 사이에 끼어 있다. 심사용 정보라 처음 온 사람에게는 흐름을 흐린다.

이 작업은 **휴대폰 폭에서 글을 지우지 않고 접거나 숨기는 것**이다. 문구는 한 글자도 바꾸지 않고, PC 화면은 그대로 둔다.

- 저장소: `gyunghun1214/blue-bio-map`, 최신 `main`에서 시작
- 작업 브랜치: 세션에 지정된 브랜치. 없으면 `ui/mobile-compact-text`
- 모바일 기준: 첫 화면(`.gate …`)은 `max-width:760px`(`intro.css`와 같게), 그 밖은 `max-width:740px`

## 원칙

1. **문구는 그대로 DOM에 남긴다.** 지우지 않고 숨기거나 접는다. 각 탭의 `textContent`는 전후로 같아야 한다(검사들이 `textContent`로 읽는다).
2. **새로 붙는 '더 보기' · '접기' 글자는 `textContent`에 넣지 않는다.** `<summary>`는 비워 두고 `aria-label="더 보기"`를 달며, 보이는 글자는 CSS `::before`의 `content`로 그린다.
3. **PC(741px 이상, 첫 화면은 761px 이상)는 지금과 똑같이 보인다.** 접힌 내용이 PC에서는 항상 펼쳐져 있고 '더 보기' 버튼은 보이지 않는다.
4. **스크립트가 실패해도 글은 보인다.** `<details>`는 HTML에서 `open`으로 두고, 모바일일 때만 스크립트가 닫는다.
5. CSS는 새 파일 **`dist/mobile-compact.css`** 하나에 모은다. `index.html`에서 모든 CSS 중 마지막에 불러온다(`mobile-type.css`가 있으면 그 다음). 맨 위에 설명 주석을 단다. 기존 CSS 파일은 고치지 않는다.

## 할 것

### 1. 탐색 지도: 설명 글을 '읽는 법 ⓘ' 아래 시트로 모으기

**먼저 지금 구조를 확인한다.** 지도 영역에 이미 '읽는 법 ⓘ' 버튼이 있다. 이 버튼이 지금 무엇을 여는지, 범례 문단·'색의 의미'·'지도 읽는 법'·'그 밖의 기능 · 배경 지도 출처'가 각각 어느 요소인지, 같은 부모 아래에 있는지 확인해 README에 적는다. 휴대폰 종 정보용 아래 시트가 이미 있으면 그 구조와 CSS를 재사용한다.

- **모바일에서 지도 아래 흐름에서 빼는 것**: 범례 긴 문단(셀 색·4° 셀·조사량 음영 설명), '색의 의미', '지도 읽는 법', '그 밖의 기능 · 배경 지도 출처'
- **모바일에서도 지도 위·아래에 남기는 것**: 한 줄 색 칩 범례(유형 색, 조사량 적음↔많음 막대), 선택 종 칩(기록 셀 수·기록 수·연도), '읽는 법 ⓘ' 버튼. 지도를 읽는 데 꼭 필요한 최소한이다.
- **시트 만들기**
  - 위 네 덩어리를 **DOM에서 옮기지 않는다.** 네 덩어리가 한 부모 아래에 있으면 그 부모를, 아니면 `index.html`에서 네 덩어리를 감싸는 `<div class="map-guide" id="map-guide">` 하나를 더해 그것을 모바일에서 시트로 보이게 한다(`position:fixed`, 화면 아래, CSS만). 감싸기 전후로 `textContent`가 같은지 확인한다.
  - 시트: 화면 아래에서 올라오고, 높이는 최대 `75vh`, 안에서만 스크롤한다. 맨 위에 제목 '지도 읽는 법'(기존 제목 요소가 있으면 그것을 쓰고 새 문구를 만들지 않는다)과 닫기 버튼 ✕(기존 닫기 버튼 스타일, `aria-label="닫기"`)을 둔다.
  - 열기: 모바일에서 '읽는 법 ⓘ'를 누르면 시트가 열린다. 버튼에 `aria-expanded`, `aria-controls="map-guide"`를 단다.
  - 닫기: ✕, 뒤 배경 탭, Esc. 닫히면 포커스를 '읽는 법 ⓘ' 버튼으로 돌려준다.
  - 열려 있는 동안: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`(시트 제목), 포커스를 시트 제목으로 옮기고 시트 안에서만 순환시킨다. 뒤 페이지 스크롤을 잠근다.
  - 색은 심해 토큰(`--cs-panel`, `--cs-line` 등 탐색 탭에서 쓰는 대응 토큰)을 쓴다.
  - '움직임 줄이기'가 켜져 있거나 `prefers-reduced-motion`이면 올라오는 애니메이션 없이 바로 나타난다.
- **PC**: 네 덩어리는 지금 자리에 지금 모양으로 보이고, '읽는 법 ⓘ'는 지금 동작 그대로다. 시트 스타일은 모바일 미디어 쿼리 안에만 둔다.
- 폭이 바뀌어(휴대폰 회전 등) 741px 이상이 되면 열린 시트를 닫고 잠금을 푼다.

### 2. 비교와 지표 · 근거와 방법: 첫 문장만 보이고 나머지는 접기

**접는 방식 (공통)**

```html
<li><b>MFPI · 식량</b> 첫 문장입니다.<details class="mc-more" open><summary aria-label="더 보기"></summary><span>나머지 문장들…</span></details></li>
```

- 첫 문장(또는 첫 줄)은 `<details>` 밖에 그대로 둔다. 둘째 문장부터를 `<details class="mc-more" open>` 안으로 옮긴다. 문장 사이 공백 하나까지 맞춰 `textContent`가 전후로 같게 한다.
- `<summary>`는 비워 두고 `aria-label="더 보기"`를 단다. CSS로 `summary::before{content:"더 보기"}`, `details[open]>summary::before{content:"접기"}`를 그린다. 글자는 13px 이상, 민트(`--mt-accent` 또는 탭의 대응 토큰), 누르는 영역은 높이 44px 이상이다.
- 스크립트: `matchMedia('(max-width:740px)')`가 맞으면 페이지를 열 때 `.mc-more`의 `open`을 지운다. 폭이 741px 이상으로 바뀌면 다시 `open`을 붙인다. 사용자가 연 것은 같은 폭 안에서는 그대로 둔다.
- PC CSS: `@media (min-width:741px){ .mc-more>summary{display:none} }`. PC에서는 늘 펼쳐져 있고 버튼이 없다. 접힌 부분이 문단 안에서 줄바꿈 없이 이어 보이도록 `details`·내부 `span`을 `display:inline`으로 둔다. **PC 화면 캡처가 전후로 같아야 한다.**
- 화면 안 찾기(Ctrl+F, 휴대폰 '페이지에서 찾기')로 접힌 글을 찾으면 펼쳐지는지 Chrome에서 확인한다. 안 되면 README에 적는다(고치지 않아도 된다).

**접는 곳**

| 탭 | 대상 | 모바일에서 보이는 것 | 접는 것 |
|---|---|---|---|
| 비교와 지표 | '읽는 법' 팝업의 목록(MCUI 괄호, 두 값 따로, 자원 감소 신호, **밀집 구간**, 종 프로필 숫자) | 앞 두 항목 | 나머지 항목 전체를 `<details>` 하나로 |
| 비교와 지표 | '읽는 법' 팝업의 '쉬운 이름과 공식 유형 이름' 표 아래 설명 문단 | 첫 문장 | 나머지 문장 |
| 근거와 방법 | 01 '국가 해양생물 시스템과 함께 읽기' 4열 표 | 표 위 설명 문단('종 정보·분포·실물 소재는 국가 시스템이 맡고 …') | 표와 그 아래 출처 줄을 `<details>` 하나로 |
| 근거와 방법 | 02 '세 지표의 근거' 목록의 MFPI · MBPI · MCUI 항목 | 각 항목의 `<b>` 제목 + 첫 문장 | 둘째 문장부터 |
| 근거와 방법 | 02 '왜 MBPI의 주 소스가 ChEMBL인가요?' | 첫 문단 | 둘째 문단(CMNPD 표기) |
| 근거와 방법 | 03 '규칙 고정' 목록 항목 중 두 문장 이상인 것 | `<b>` 제목 + 첫 문장 | 둘째 문장부터 |
| 근거와 방법 | 03 '자료를 읽을 때' 목록 | 앞 세 항목 | 나머지 항목 전체를 `<details>` 하나로 |
| 근거와 방법 | 03 '유형과 셀 색' 표 아래 설명 문단 | 첫 문장 | 나머지 문장 |

- 항목이 한 문장뿐이면 접지 않는다.
- **목록 항목의 시작 마크업은 바꾸지 않는다.** 검사가 `<li><b>…`로 시작하는지 보는 줄이 있다(`test_verified_ui.mjs`의 '의약 후보 MBPI' 줄 등). `<li>`에 class를 달지 말고, `<details>`는 첫 문장 **뒤에만** 넣는다.
- 목록 여러 항목을 접을 때는 남은 `<li>`들을 `<details>` 안의 별도 `<ul>`로 옮기지 말고, 원래 `<ul>` 바로 뒤에 `<details class="mc-more" open><summary …></summary><ul class="…원래 class…">나머지 li</ul></details>`를 둔다. 원래 목록과 같은 class를 달아 모양이 같게 한다. 번호를 CSS counter로 다는 목록('자료를 읽을 때' 01~10)은 번호가 이어지는지 확인한다(`counter-reset` 위치).
- 흐름도 상자를 눌러 카드로 이동하는 동작, `.flash`, 검증 기록 표는 건드리지 않는다. 흐름도에서 넘어온 카드 안 `.mc-more`는 닫힌 채로 둔다.
- `app.js`가 채우는 영역(검증 기록, 유형 표 등)은 이번 범위가 아니다. 정적 HTML의 문단만 접는다.

### 3. 첫 화면: 대회 연결 문구 모바일에서 숨기기

- 숨기는 것(`max-width:760px`에서 `display:none`):
  - 제목 위 'Ocean 20 Challenge · 해양 10대 과제 3 … · 2 …' 줄
  - '해결' 아래 '흩어진 자료를 잇고, 오늘의 이용과 다음 세대의 바다를 잇는 지도 · 2026 세계해양포럼 대주제 「해양, 잇다」 · UN Ocean Decade …' 줄
- 두 줄의 실제 선택자(`.gate-kicker`, `.gate-connect` 등)를 먼저 확인한다. **다른 문구가 같은 요소에 섞여 있으면** 그 요소 전체를 숨기지 말고 README에 적은 뒤 대회 문구 부분만 감싸는 `<span>`을 더해 그것만 숨긴다(`textContent` 동일).
- 제목 위 '한반도 주변 바다의 해양생물 근거 지도' 같은 다른 안내 줄은 그대로 둔다.
- 숨긴 뒤 '문제 → 해결 → 바다 탐색하기 · 지표 살펴보기' 버튼이 390px 첫 화면 안(스크롤 없이)에 더 가깝게 올라오는지 본다. 지구본이 글과 겹치면 지구본 크기 계산(`layout()`)은 고치지 말고 여백만 조정한다. `layout()`이 숨긴 요소의 위치를 모으고 있으면 크기 0인 요소를 건너뛰는지 확인한다.
- '근거와 방법' 맨 아래 '첫 화면의 대회 주제 연결' 출처 문단은 그대로 둔다(심사위원이 확인할 수 있는 자리).

## 절대 바꾸지 않을 것

- 모든 탭의 **문구** 한 글자도(`textContent` 전후 동일). 새 글자는 CSS `content`와 `aria-label`로만 더한다
- **PC 화면**(741px 이상, 첫 화면 761px 이상): 1440px 캡처가 전후로 같아야 한다
- 지표 값, 표의 행, 흐름도 SVG, 지도 그리기, 매트릭스
- 목록 항목의 시작 마크업(`<li><b>…`), 기존 `id`, `data-*`, `role`, `aria-*`
- `scripts/`, `config/`, `dist/*.json`
- `expedition.html`, 멍이

## 검사

1. 먼저 바뀌는 곳에 묶인 검사를 찾는다. `verification/` 아래에서 `gate-kicker`, `gate-connect`, `Ocean 20`, `세계해양포럼`, `map-legend`, `색의 의미`, `지도 읽는 법`, `그 밖의 기능`, `cmp-read`, `밀집 구간`, `MBRIS`, `자료를 읽을 때`, `isVisible`, `toBeVisible`, `innerText`로 검색한다.
   - 보이는지(visible)를 보는 기대값이 이번 변경과 충돌하면 **기대값을 고친다**(모바일에서는 숨김·접힘, PC에서는 보임). 지우거나 건너뛰지 않는다.
2. 새 검사를 더한다(Playwright/uicheck 방식).
   - 네 화면(첫 화면, 탐색 지도, 비교와 지표, 근거와 방법)의 `textContent`가 전후로 같다(390px, 1440px 모두).
   - 1440px: `.mc-more`가 모두 `open`이고 `summary`가 보이지 않는다. 탐색 지도 설명 네 덩어리가 지금 자리에 보인다. 첫 화면 대회 문구 두 줄이 보인다.
   - 390px: 탐색 지도 아래 흐름에 설명 네 덩어리가 보이지 않는다. '읽는 법 ⓘ'를 누르면 시트가 열리고 네 덩어리가 보인다. Esc·✕·배경 탭으로 닫히고 포커스가 버튼으로 돌아온다.
   - 390px: `.mc-more`가 모두 닫혀 있고, 각 `summary`의 접근 가능한 이름이 '더 보기'다. 누르면 펼쳐진다.
   - 390px: 첫 화면 대회 문구 두 줄이 보이지 않는다.
   - '의약 후보 MBPI' 등 기존 `<li><b>…` 시작 검사가 그대로 통과한다.
3. CI 전체(`verify.yml`의 `node verification/test_*.mjs`, `python scripts/build_expedition_stops.py --check`, `python -m unittest discover -s verification -p 'test_*.py'`)와 로컬 `verification/uicheck.mjs`를 돌린다.
4. 직접 확인한다.
   - 360 · 390 · 768 · 1100 · 1440px에서 가로 넘침이 없다(`document.documentElement.scrollWidth <= clientWidth`).
   - 시트가 열린 동안 뒤 페이지가 스크롤되지 않고, 시트 안 긴 글은 시트 안에서 스크롤된다. iOS Safari에서 주소창이 줄어들 때 시트 아래가 잘리지 않는다(`100dvh`/`env(safe-area-inset-bottom)` 확인).
   - 키보드 포커스 링이 '더 보기'와 시트 안에서 보인다.
   - 흐름도 상자를 누르면 해당 카드로 이동하고 `.flash`가 붙는다(세 단계 모두).
   - 콘솔 오류가 없다.

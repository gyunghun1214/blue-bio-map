# 휴대폰에서 멍이 버튼·안내 말풍선이 내용을 가리지 않게 — Claude Code 작업 지침

## 배경

휴대폰(390px)에서 멍이 버튼(`.bbc-fab`, 48×48)이 모든 탭의 오른쪽 아래에 떠 있어 내용을 가린다. 2026-10-25 `main`(be04cb3)을 390×844로 띄워 확인한 것은 다음과 같다.

| 화면 | 가려지는 것 |
|---|---|
| 탐색 지도 | 종 카드 줄(가로 스크롤)의 둘째 카드 이름·학명·배지. 처음 들어오면 말풍선 '멍이가 사용법을 알려드릴게요'가 첫 카드까지 덮는다 |
| 탐색 지도 · 종 상세 | 오른쪽 끝의 펼침 화살표(`근거 상태` 등), 마지막 줄 링크 |
| 비교와 지표 | 매트릭스 범례 오른쪽 끝, 종 프로필의 '바다 탐험에서 보기 ↗', 담기 트레이 오른쪽 |
| 근거와 방법 | 접이식 제목의 `+`, 긴 출처 문단 오른쪽 끝, 꼬리말 '의견 보내기' |

지금 구조(`dist/chatbot.js`, `dist/chatbot.css`, `dist/theme.css`)는 다음과 같다.

- 버튼: `position:fixed; right:var(--bbc-right); bottom:calc(16px + var(--bbc-bar,0px))`. `--bbc-bar`는 `theme.css`가 740px 이하에서 아래 탭바 높이(`56px + safe-area`)로 정한다.
- 페이지 아래 여백: `body{padding-bottom:var(--bbc-bar)}`뿐이라, **맨 아래까지 스크롤해도 마지막 줄 오른쪽이 버튼 아래에 남는다.**
- 말풍선(`.bbc-hint`): 이미 첫 방문 한 번만 뜬다(`localStorage` `bbChatHintSeen`). 첫 화면이 닫힌 뒤 7초(`HINT_MS`) 동안 보이고, 스크롤하거나 멍이 밖을 누르면 접힌다. 다만 **버튼 왼쪽 같은 높이**(`bottom:calc(22px + var(--bbc-bar))`)에 뜨므로 휴대폰 탐색 지도에서는 종 카드 줄 위에 정확히 겹친다.
- 사용자가 버튼을 끌어 옮긴 자리(`bbChatFabPos`, PC·휴대폰 따로)는 저장되고 기본 자리보다 우선한다.
- 휴대폰 판단 기준이 둘이다. 멍이는 `max-width:767.98px`, 탭바는 `max-width:740px`.

이 작업은 **휴대폰 폭에서** 멍이가 내용을 가리지 않게 하는 것이다. 멍이 기능, 대화 내용, PC 화면은 바꾸지 않는다.

- 저장소: `gyunghun1214/blue-bio-map`, 최신 `main`에서 시작
- 작업 브랜치: 세션에 지정된 브랜치. 없으면 `ui/mascot-mobile-overlap`
- 적용 범위: 아래 1~3번은 `max-width:740px`(탭바가 있는 폭). 741~767px의 동작은 지금과 같게 둔다.

## 할 것

### 1. 스크롤하는 동안 버튼을 작게 접기

- 페이지(또는 각 탭의 실제 스크롤 요소)가 스크롤되기 시작하면 `.bbc`에 `bbc-tucked` class를 붙이고, 스크롤이 멈추고 **약 700ms** 뒤에 뗀다.
- 접힌 모양: 버튼을 화면 오른쪽 가장자리 쪽으로 반쯤 밀어 넣고(`transform:translateX(…)`, 버튼 폭의 약 55%), 불투명도 0.55. 크기를 줄이는 대신 밀어 넣는 이유는 누르는 영역(48px)을 그대로 두기 위해서다.
  - 사용자가 버튼을 왼쪽 절반으로 옮겼으면 왼쪽 가장자리로 밀어 넣는다(`chatbotFabAnchor`의 `h`를 그대로 쓴다). 위·아래로 옮긴 경우도 같은 방식이다.
- 접힌 버튼을 누르면 먼저 펼쳐지기만 하고 대화창은 열지 않는다. 펼친 뒤 다시 누르면 지금처럼 열린다. 끌어 옮기기(드래그)는 접힌 상태에서 시작해도 지금과 같이 동작해야 한다.
- 버튼에 키보드 포커스가 있으면(`:focus-visible`) 접지 않는다. 대화창이 열려 있으면 접지 않는다.
- 움직임: `prefers-reduced-motion`이거나 '움직임 줄이기'가 켜져 있으면 전환 애니메이션 없이 바로 바뀐다. 아니면 `transform`·`opacity`에 0.2s 전환을 준다.
- 스크롤 리스너는 `{passive:true}`로 달고, `requestAnimationFrame`으로 묶어 스크롤마다 레이아웃을 읽지 않는다.
- 지도 끌기(Leaflet 패닝)와 종 카드 줄의 **가로** 스크롤에서도 접는다(둘 다 손가락이 버튼 근처를 지나간다). 지도는 `movestart`/`moveend`, 카드 줄은 그 요소의 `scroll` 이벤트를 쓴다.

### 2. 맨 아래까지 내리면 가려지는 줄이 없게

- 740px 이하에서 각 탭 맨 아래에 버튼 높이만큼 여백을 더한다: `body` 아래 여백을 `calc(var(--bbc-bar) + 48px + 16px)`로. 이미 `#compare`처럼 담기 트레이 때문에 더 큰 여백을 둔 곳은 그 값이 더 크면 그대로 둔다.
  - `theme.css`의 원래 줄은 고치지 않는다. 덮어쓰는 규칙은 `chatbot.css`의 휴대폰 미디어 쿼리 안에 둔다(멍이 때문에 생긴 여백이므로).
  - 사용자가 버튼을 위쪽으로 옮겼으면 이 여백은 필요 없지만, 단순하게 하기 위해 그대로 둔다(README에 적는다).
- 종 카드 줄(가로 스크롤)의 끝에도 오른쪽 여백 `56px`를 더해, 마지막 카드를 버튼 왼쪽까지 끌어올 수 있게 한다. 카드 줄의 실제 선택자를 먼저 확인한다.
- 탐색 지도의 아래 시트(종 목록·상세)가 자체 스크롤 상자라면, 그 상자에도 같은 아래 여백을 준다.

### 3. 첫 안내 말풍선을 버튼 위로

- 740px 이하에서 말풍선을 버튼 **왼쪽**이 아니라 **바로 위**에 띄운다. 오른쪽 끝을 버튼 오른쪽 끝에 맞추고, 아래 끝은 버튼 위 8px. 폭은 `max-width:calc(100vw - 32px)`.
  - 사용자가 버튼을 옮긴 경우(`placeMoved`)는 지금 규칙(옆으로)을 그대로 쓴다. 단, 휴대폰에서 옆에 띄울 자리가 120px보다 좁으면 위(버튼이 아래쪽 절반일 때) 또는 아래(위쪽 절반일 때)로 띄운다.
- 탐색 지도에서 말풍선이 **종 카드 줄과 겹치면** 말풍선을 더 위로 올리지 말고, 종 카드 줄이 보이지 않는 동안(아래 시트가 접혀 있을 때 등)으로 미루지도 않는다. 대신 말풍선이 뜬 7초 동안 겹치는 것은 허용하되, **카드 줄을 가로로 스크롤하거나 카드를 누르면 바로 접히게** 한다(지금은 세로 스크롤과 멍이 밖 누르기만 접는다). 카드 누르기는 지금 `pointerdown` 처리로 이미 접히는지 확인하고, 가로 스크롤만 더한다.
- 문구, 7초, 한 번만 띄우는 규칙(`bbChatHintSeen`)은 바꾸지 않는다.

## 절대 바꾸지 않을 것

- **PC(741px 이상)** 의 버튼 자리·크기·말풍선 위치·대화창 위치. 1440px 캡처가 전후로 같아야 한다
- 멍이 그림, 표정·깡충 애니메이션, 대화창(아래 시트) 크기와 내용, FAQ 답변 문구
- 끌어 옮기기 동작과 저장 형식(`bbChatFabPos`, `chatbotReadFabPos`·`chatbotClampFab`·`chatbotFabAnchor`·`chatbotPanelPlace` 함수의 입출력). 이 함수들은 `test_chatbot_drag.mjs`가 직접 부른다
- 말풍선 문구, 표시 시간 7초, 한 번만 띄우는 규칙
- 아래 탭바, 담기 트레이, 다른 탭의 레이아웃·문구, `expedition.html`
- `scripts/`, `config/`, `dist/*.json`
- 새 화면 문구를 만들지 않는다. `aria-label`·`title`도 지금 것을 그대로 쓴다

## 캐시

- `chatbot.js`·`chatbot.css`를 고쳤으므로 `index.html`의 `?v=` 해시를 다시 계산한다(README 53행 규칙, LF로 맞춘 파일 내용 sha256 앞 10자, `test_client_outdated.mjs`). `theme.css`를 고치지 않았는지 확인한다.

## 검사

1. 먼저 관련 검사를 찾는다. `verification/` 아래에서 `bbc-fab`, `bbc-hint`, `bbChatHintSeen`, `bbChatFabPos`, `bbc-bar`, `padding-bottom`으로 검색한다(`test_chatbot_drag.mjs`, `test_chatbot_faq.mjs`, `uicheck.mjs` 1585~1690행 근처, `2026-10-25-mobile-ux/*.mjs`).
   - 기대값이 이번 변경과 충돌하면 **기대값을 고친다.** 지우거나 건너뛰지 않는다. 특히 `uicheck.mjs` 1641행의 `m.bottom===16`처럼 버튼 자리를 재는 검사는 접힌 상태가 아닐 때 재도록 한다.
2. 새 검사를 더한다(Playwright/uicheck 방식, 390×844, `isMobile`, `hasTouch`).
   - **가림 없음**: 네 화면(탐색 지도, 탐색 지도 종 상세, 비교와 지표, 근거와 방법)을 각각 맨 아래까지 스크롤하고 700ms 기다린 뒤, 버튼 사각형과 겹치는 **보이는** `a, button, summary, [role=button], input`이 없다(멍이 자신과 아래 탭바 제외).
   - **접기**: `window.scrollBy(0,300)` 직후 `.bbc`에 `bbc-tucked`가 있고 버튼의 `getBoundingClientRect().width`가 48 그대로이며, 1초 뒤에는 class가 없다.
   - **접힌 버튼 누르기**: 접힌 상태에서 버튼을 탭하면 대화창(`.bbc-panel`)은 `hidden`이고 `bbc-tucked`만 빠진다. 한 번 더 탭하면 열린다.
   - **포커스**: 버튼에 포커스를 준 채 스크롤하면 접히지 않는다.
   - **말풍선 위치**: `bbChatHintSeen`을 지운 새 세션에서 말풍선의 `bottom`이 버튼 `top`보다 작거나 같고(버튼 위), 오른쪽 끝 차이가 2px 이내다.
   - **말풍선 접힘**: 종 카드 줄을 가로로 200px 스크롤하면 말풍선이 `hidden`이 되고 `bbChatHintSeen`이 저장된다.
   - **옮긴 버튼**: `bbChatFabPos`에 왼쪽 위 자리를 넣고 열면, 스크롤 때 왼쪽으로 밀려 접힌다.
   - **PC 그대로**: 1440×900에서 스크롤해도 `bbc-tucked`가 붙지 않고, 버튼 `right`·`bottom`이 전과 같다.
3. CI 전체(`verify.yml`의 `node verification/test_*.mjs`, `python scripts/build_expedition_stops.py --check`, `python -m unittest discover -s verification -p 'test_*.py'`)와 로컬 `verification/uicheck.mjs`를 돌린다.
4. 직접 확인한다.
   - 360 · 390 · 768 · 1440px에서 가로 넘침이 없다(`scrollWidth <= clientWidth`). 접힌 버튼이 화면 밖으로 밀려 가로 스크롤을 만들지 않는지 특히 본다.
   - 실제 휴대폰(iOS Safari, Android Chrome) 하나 이상: 관성 스크롤 중 깜빡임이 없고, 스크롤을 멈추면 버튼이 돌아온다. iOS 주소창이 줄었다 늘어날 때 버튼이 탭바와 겹치지 않는다.
   - '움직임 줄이기'를 켜면 전환 없이 바로 바뀐다.
   - 콘솔 오류가 없다.

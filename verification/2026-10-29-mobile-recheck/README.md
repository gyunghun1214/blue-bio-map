# 휴대폰 화면 다시 점검과 고침 (2026-10-29)

LKH 요청: 휴대폰 화면을 직접 둘러보고 글씨 배치·넘침과 쓰기 불편한 곳을 찾아(14가지, 점검 보고서는 프로젝트 파일
`mobile-audit-2026-10-29/README.md`) 모두 고치기. 기준 main `dd62dcc`(#280). 클라우드 Chromium에서 휴대폰 흉내(isMobile·터치,
움직임 줄이기)로 확인했다. LKH PC는 쓰지 않았다. 실제 아이폰 Safari·삼성 인터넷은 아니다.

## 지킨 것

- PC 화면은 그대로: 바꾼 규칙은 모두 휴대폰 폭(740·760px 이하), 가로 휴대폰(741–1179px × 높이 500px 이하), 손가락 기기
  (`pointer:coarse`) 안에만 있다. `verification/2026-10-25-mobile-ux/pc-diff.mjs`로 1440×900·1280×720을 main(#282 병합본)과 픽셀 비교했다. 탐색 지도·비교와 지표(매트릭스·데이터 표)·근거와 방법, 첫 화면·전체 길이, 움직임 줄이기·보통 32장 × 2라운드에서 고정된 차이 0.
- 글자는 바꾸지 않았다(10번 꼬리표 하나를 뺀 것뿐). i18n 기준 파일 그대로.
- CSS 순서 그대로(mobile-type → mobile-compact → mobile-dedupe → map-attribution → meongi.css 맨 끝). 새 글씨 13px 이상.
- `?v=`는 파일 내용 해시 앞 10자로 다시 찍음(test_client_outdated).

## 자동 검사 전후 (화면을 0.8화면씩 내리며 찾은 수)

| 화면 | 낱말 중간 끊김 | 13px 미만 | 한두 글자 줄 |
|---|---|---|---|
| 360×780 한국어 | 30 → 3 | 35 → 0 | 20 → 5 |
| 390×844 한국어 | 30 → 2 | 36 → 0 | 11 → 2 |
| 430×932 한국어 | 22 → 3 | 38 → 2 | 4 → 1 |
| 360×780 영어 | (영문) 4 → 4 | 36 → 0 | 18 → 9 |

430은 마지막 고침 전 값이다. 영어 화면의 한국어 원문 꼬리표(`.i18n-ko`, 12px)도 휴대폰에서 13px로 올렸다. 남은 낱말 끊김은 긴 파일 이름·DOI가 든 출처 줄과 시작 화면 지구 영상 출처 줄(줄 끝에 들어갈 자리가 없음)이다.
가로 화면(844·780)은 PC 배치라 PC 글씨 크기(12px)를 그대로 쓴다(PC 화면을 바꾸지 않는 규칙).

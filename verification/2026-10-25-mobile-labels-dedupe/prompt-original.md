# 모바일 영어 눈썹 글 숨김 + 탭마다 반복되는 설명 한 곳으로 모으기 — Claude Code 작업 지침

## 배경

휴대폰(390px)에서 글 줄 수를 늘리는 원인이 두 가지 더 있다.

- **대문자 영어 눈썹 글**: `MARINE EVIDENCE EXPLORER`, `EVIDENCE & METHODS`, `OUR RESEARCH SCOPE`, `THE EVIDENCE JOURNEY`, `FOOD POTENTIAL` · `BIOACTIVITY POTENTIAL` · `CONSERVATION URGENCY`, `TRACEABLE` · `COMPARABLE` · `TWO PERSPECTIVES`, `HOW TO READ` 같은 라벨이 거의 모든 제목 위에 붙어 있다. 바로 아래 한국어 제목이 같은 뜻을 말하므로 모바일에서는 정보 없이 한 줄씩만 늘린다.
- **같은 설명의 반복**: 같은 문장이 한 화면 안에서, 또 탭마다 되풀이된다. 배포본에서 확인한 예는 다음과 같다.

| 설명 | 나오는 곳 |
|---|---|
| 4° 셀은 민감종 보호를 위해 넓게 공개한 범위로, 테두리만 표시 | 탐색 지도 범례 문단 · '색의 의미' 문단(같은 문장 두 번), 근거와 방법 |
| 셀 색은 바다 부분에만 칠함 | 탐색 지도 범례 문단 · '색의 의미'(두 번), 근거와 방법 '자료를 읽을 때' |
| 붉은 점 = 기록이 있는 칸의 위치(넓게 묶음) | 탐색 지도 범례 안 세 번, 근거와 방법 '자료를 읽을 때' |
| 기록 수 = 공개 관측 기록 건수 | 탐색 지도 범례, 근거와 방법 '자료를 읽을 때' |
| 쉬운 이름은 기준선 50 위·아래를 읽은 것이고, 유형은 연구 순서를 고르기 위한 분류 | 비교와 지표 '읽는 법', 근거와 방법 '유형과 셀 색' 아래(거의 같은 문장) |
| 두 축(활용·보전)은 더하지 않고 따로 봄 | 비교와 지표 '두 축을 따로 보는 이유' · 목록 · 그래프 아래 줄, 근거와 방법 흐름도 · 'TWO PERSPECTIVES' 카드 · 2×2 설명 |
| MCUI 숫자 옆 괄호 = 그 값을 정한 범주, '어획량 감소' 표시 | 비교와 지표 '읽는 법' 목록 두 줄, 근거와 방법 '자료를 읽을 때' |
| 공식 가중치 w = 0.50 고정, 슬라이더는 탐색용 | 비교와 지표 가중치 설명, 근거와 방법 '규칙 고정' |

이 작업은 **휴대폰 폭에서** 영어 눈썹 글을 숨기고, 반복 설명은 한 곳(기준 위치)에만 보이게 하고 나머지 자리에는 짧은 링크를 두는 것이다. 문구는 한 글자도 바꾸지 않고, PC 화면은 그대로 둔다.

- 저장소: `gyunghun1214/blue-bio-map`, 최신 `main`에서 시작
- 작업 브랜치: 세션에 지정된 브랜치. 없으면 `ui/mobile-labels-dedupe`
- 모바일 기준: 첫 화면(`.gate …`)은 `max-width:760px`, 그 밖은 `max-width:740px`
- **선행 작업**: `prompts/mobile-type-scale-claude-code.md`, `prompts/mobile-compact-text-claude-code.md`가 병합된 `main`에서 시작한다. 탐색 지도의 '지도 읽는 법' 시트와 `.mc-more` 접기를 이 작업이 기준 위치·링크 대상으로 쓴다. 둘 중 하나라도 병합 전이면 작업을 시작하지 말고 그 사실만 PR 없이 보고한다.

## 원칙

1. **문구는 DOM에 그대로 둔다.** 숨기기만 한다. 각 탭의 `textContent`는 전후로 같아야 한다.
2. **새 링크의 글자는 `textContent`에 넣지 않는다.** `<a>`에 `aria-label`을 달고, 보이는 글자는 CSS `::before`의 `content`로 그린다(`mobile-compact-text`의 '더 보기'와 같은 방식).
3. **PC(741px 이상, 첫 화면 761px 이상)는 지금과 똑같이 보인다.** 새 링크는 PC에서 보이지 않는다. 1440px 캡처가 전후로 같아야 한다.
4. CSS는 새 파일 **`dist/mobile-dedupe.css`** 하나에 모으고, `index.html`에서 모든 CSS 중 마지막(`mobile-compact.css` 다음)에 불러온다. 맨 위에 설명 주석을 단다. 기존 CSS 파일은 고치지 않는다.

## A. 영어 눈썹 글 숨기기

### A1. 목록 만들기
390px에서 네 화면(첫 화면, 탐색 지도, 비교와 지표, 근거와 방법)을 열고, 보이는 요소 중 **글자가 대문자 영문·숫자·공백·`&`·`·`·`-`로만 된 것**을 스크립트로 모은다(`innerText`가 `/^[A-Z0-9 &·\-]{3,}$/`, 자식 요소가 없는 것). 결과를 README 표로 적는다: 선택자 · 글자 · 화면 · 바로 아래 한국어 제목.

### A2. 숨길 것과 남길 것
- **숨긴다** (`display:none`, 모바일 미디어 쿼리 안): 바로 아래나 옆에 같은 뜻의 한국어 제목이 있는 영어 라벨. 위 '배경'의 예가 모두 여기에 든다. `.cmp-eyebrow`, `.mt-eyebrow`, `.mt-k`처럼 눈썹 글 전용 class가 있으면 class 단위로 숨긴다. 같은 class가 다른 뜻으로도 쓰이면 해당 요소만 숨긴다.
- **남긴다**
  - 지표·자료 이름: `MBPI`, `MFPI`, `BBVI`, `MCUI`, `MBPI-Rx`, `IUCN`, `KOSIS`, `OBIS`, `GBIF`, `WoRMS`, `ChEMBL`, `CMNPD`, `EEZ`, `BBNJ`, `AphiaID` 등. 이것은 라벨이 아니라 내용이다.
  - 번호: `01` · `02` · `03`(흐름도·카드 단계 번호)
  - 영어 라벨만 있고 한국어 제목이 없는 요소(그런 것이 있으면 README에 적고 남긴다)
  - 언어 전환 `EN` 버튼, 영어 화면(`html.lang-en`)일 때의 라벨. **영어 화면에서는 아무것도 숨기지 않는다**(`html:not(.lang-en)` 또는 `:lang(ko)`로 범위를 묶는다. 실제 언어 표시 방식을 먼저 확인한다).
- 숨긴 뒤 제목 위 여백이 어색하게 남으면 그 제목의 위 여백만 조정한다.

## B. 반복 설명을 한 곳으로 모으기

### B1. 목록 만들기
390px에서 네 화면의 보이는 글을 **문장 단위**로 잘라(`。`·`.`·`다.`·줄바꿈 기준), 공백·괄호·가운뎃점을 정규화한 뒤 다음을 찾는다.
- 완전히 같은 문장
- 거의 같은 문장: 글자 2-gram 자카드 유사도 0.75 이상, 길이 20자 이상

결과를 `verification/<작업 날짜>-mobile-labels-dedupe/dedupe-groups.json`(그룹마다 문장들, 각 문장의 화면·선택자)과 README 표로 남긴다. 위 '배경' 표의 여덟 그룹이 목록에 나오는지 확인하고, 더 나온 그룹은 아래 규칙대로 처리하거나 '그대로 둠'과 이유를 적는다.

### B2. 기준 위치 정하기
| 설명 종류 | 기준 위치(모바일에서 전체 문장이 보이는 곳) |
|---|---|
| 지도 표시 규칙(4° 셀, 바다만 칠함, 붉은 점, 기록 수, 버블) | 탐색 지도 '지도 읽는 법' 시트 |
| 매트릭스·지표 해석(기준선 50, 쉬운 이름과 유형, 두 축 따로, MCUI 괄호, 가중치 0.50) | 근거와 방법의 해당 항목(03 '규칙 고정', '자료를 읽을 때', '유형과 셀 색') |

규칙은 다음과 같다.

1. **한 화면 안의 반복**(탐색 지도 범례 문단과 '색의 의미'의 같은 문장 등): 화면 안에서 첫 번째 것만 보이고 나머지는 숨긴다. 링크는 달지 않는다.
2. **탭 사이의 반복**: 기준 위치가 아닌 탭에서는 전체 문장을 숨기고, 그 자리에 기준 위치로 가는 짧은 링크 하나를 둔다. 한 덩어리 안에 숨긴 문장이 여러 개면 링크는 하나만 둔다.
3. **남기는 것**: 그래프·지도 바로 옆의 짧은 라벨·칩·범례(예: '4° 공개 셀 · 민감종 보호로 넓게 공개 (테두리만)' 칩, '각각 50 이상이면 높음', 축 이름, '두 축은 따로 봅니다 · 점 위치가 곧 판단입니다'처럼 한 줄짜리 그래프 캡션)는 숨기지 않는다. 그 화면을 읽는 데 바로 필요한 것이다. 숨기는 대상은 **두 문장 이상의 설명 문단이나 목록 항목**이다.
4. 기준 위치의 문장이 `mobile-compact-text`에서 `.mc-more` 안에 접혀 있으면, 링크로 넘어왔을 때 그 `<details>`를 펼친다.
5. **문장 일부만 겹치는 목록 항목**(예: 비교와 지표 '읽는 법'의 '두 값은 따로 봅니다 · 점 색은 유형입니다 · …')은 숨기지 않는다. 겹치는 부분만 잘라 숨기려고 마크업을 쪼개지 않는다.

### B3. 링크 만들기
```html
<a class="see-also" href="#method-03" data-see="method-03" aria-label="근거와 방법에서 자세히 보기"></a>
```
- 보이는 글자는 CSS로 그린다: `.see-also::before{content:"근거와 방법에서 자세히 보기 →"}`(지도 시트로 가는 링크는 `"지도 읽는 법 보기 →"`). 13px 이상, 탭의 링크 색(민트 토큰), 누르는 높이 44px 이상.
- PC: `@media (min-width:741px){ .see-also{display:none} }`.
- 이동 방식: 탭을 바꾸는 기존 장치를 먼저 찾아 그대로 쓴다(첫 화면 '전체 출처·방법 보기→', 종 상세 '비교와 지표에서 보기 →', 흐름도 상자 → 카드 이동 등). 새 라우터를 만들지 않는다.
  - 근거와 방법 대상: 탭을 열고 대상 요소로 스크롤하고, 대상이 접혀 있으면 펼치고, 흐름도 이동과 같은 `.flash`를 붙인다.
  - 지도 시트 대상: 탐색 지도 탭을 열고 '지도 읽는 법' 시트를 연다(시트를 여는 기존 함수를 부른다).
- 링크로 이동한 뒤 브라우저 뒤로 가기가 원래 탭으로 돌아가는지 확인한다. 기존 탭 이동이 해시를 쓰지 않으면 이번에도 쓰지 않는다(README에 적는다).
- 링크 대상 요소에 `id`가 없으면 `id`만 더한다. 기존 `id`는 바꾸지 않는다.

### B4. 숨기는 방식
- 숨길 문장이 독립된 요소(`<p>`, `<li>`)면 그 요소에 class(예: `dup-m`)를 달고 모바일에서 `display:none` 한다. **`<li>`의 시작 마크업이 검사 대상인 줄(`<li><b>의약 후보 MBPI…` 등)에는 class를 달지 않는다.** 그런 줄은 숨기지 않는다.
- 숨길 문장이 다른 문장과 한 요소에 섞여 있으면 그 문장만 `<span class="dup-m">`으로 감싼다. 감싸기 전후로 `textContent`가 같은지 확인한다(문장 사이 공백 포함).
- `app.js`가 그리는 글(범례 일부, 툴팁, 검증 기록 등)은 이번 범위가 아니다. 정적 HTML만 다룬다. 반복이 `app.js` 쪽에서 나오면 README에 '범위 밖'으로 적는다.

## 절대 바꾸지 않을 것

- 모든 탭의 **문구** 한 글자도(`textContent` 전후 동일). 새 글자는 CSS `content`와 `aria-label`로만 더한다
- **PC 화면**(741px 이상, 첫 화면 761px 이상): 1440px 캡처가 전후로 같다
- **영어 화면**(`EN` 전환 상태): 눈썹 글을 숨기지 않는다. 반복 숨김도 영어 화면에서는 적용하지 않는다
- 지도·매트릭스 위 칩·범례·축 이름, 지표 이름, 단계 번호
- 지표 값, 표의 행, 흐름도 SVG, `scripts/`, `config/`, `dist/*.json`
- 기존 `id`, `data-*`, `role`, `aria-*`, 목록 항목의 시작 마크업
- `expedition.html`, 멍이

- `dist/_headers`의 immutable 목록에 `/mobile-dedupe.css`를 넣는다.
- `index.html`에서 `mobile-dedupe.css?v=<LF로 맞춘 파일 내용 sha256 앞 10자>`로 불러온다. `app.js`를 고쳤으면 그 해시도 다시 계산한다(README 53행 규칙, `test_client_outdated.mjs`).

## 검사

1. 먼저 바뀌는 곳에 묶인 검사를 찾는다. `verification/` 아래에서 `eyebrow`, `mt-k`, `cmp-eyebrow`, `EVIDENCE`, `TRACEABLE`, `HOW TO READ`, `민감종`, `바다 부분`, `붉은 점`, `기준선 50`, `isVisible`, `toBeVisible`, `innerText`로 검색한다.
   - 보이는지를 보는 기대값이 충돌하면 **기대값을 고친다**(모바일 한국어 화면에서는 숨김, PC·영어 화면에서는 보임). 지우거나 건너뛰지 않는다.
2. 새 검사를 더한다(Playwright/uicheck 방식).
   - 네 화면의 `textContent`가 전후로 같다(390px · 1440px, 한국어 · 영어).
   - 390px 한국어 화면: A1 방식으로 찾은 대문자 영어 라벨 중 허용 목록(지표·자료 이름, 단계 번호) 밖의 것이 보이지 않는다.
   - 390px 영어 화면, 1440px: 눈썹 글이 지금처럼 보인다.
   - 390px: `dedupe-groups.json`의 처리 대상 그룹마다 화면 하나에 보이는 문장이 하나 이하이고, 기준 위치의 문장은 보인다.
   - 390px: 모든 `.see-also`의 접근 가능한 이름이 비어 있지 않고, 누르면 대상 탭이 열리고 대상 요소가 화면 안에 보이며, 대상이 접혀 있었으면 펼쳐진다. 지도 시트 대상이면 시트가 열린다.
   - 1440px: `.see-also`가 보이지 않는다.
3. CI 전체(`verify.yml`의 `node verification/test_*.mjs`, `python scripts/build_expedition_stops.py --check`, `python -m unittest discover -s verification -p 'test_*.py'`)와 로컬 `verification/uicheck.mjs`를 돌린다.
4. 직접 확인한다.
   - 360 · 390 · 768 · 1100 · 1440px에서 가로 넘침이 없다(`document.documentElement.scrollWidth <= clientWidth`).
   - 각 화면을 처음부터 끝까지 읽었을 때, 숨긴 문장 때문에 앞뒤 문장이 어색하게 이어지는 곳이 없다(예: '이것은'처럼 숨긴 문장을 가리키는 말).
   - 키보드로 `.see-also`에 포커스가 가고 링이 보인다.
   - 콘솔 오류가 없다.

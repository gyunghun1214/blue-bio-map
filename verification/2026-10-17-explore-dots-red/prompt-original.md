# 탐색 지도 점·버블 색을 이전 빨간색으로 되돌리기 — Claude Code 작업 지침

## 배경

탐색 지도 '출현 기록' 보기의 **도식적 점**(확대했을 때 공개 셀 안에 고정한 무늬 점)과 **버블**(축소했을 때 공개 셀을 해역별로 묶은 원, 숫자 = 셀 수)은 지금 청회색이다. 남색 지도 작업(2026-10-11, `prompts/explore-navy-map-claude-code-v2.md`) 전에는 **빨간색**이었다. 공유 미리보기(`og:image:alt`)에는 아직 '도식적 붉은 점'이라고 적혀 있다.

이 작업은 점과 버블의 색만 그 이전 빨간색으로 되돌리는 것이다. **화면 표시만 바꾼다.**

바꿀 대상(위성 배경 · '출현 기록' 보기 기준):

- 축소 지도의 **숫자 버블**(지금 청회색 원 + 흰 테두리 + 숫자). 크기는 모인 셀 수, 진하기는 셀당 기록 수 구간
- 확대 지도의 **셀별 도식적 점**
- 왼쪽 아래 접힌 범례 줄 '버블 = 공개 셀 묶음 · 숫자 = 셀 수' 앞의 **회색 원 견본**, 펼친 범례 안의 점·버블 견본

바꾸지 않을 것(헷갈리기 쉬운 것):

- 왼쪽 위 칩('톳 · 공개 셀 16개 · 기록 1,032건') 앞의 초록 점 — 선택 종의 유형 색이다
- 오른쪽 종 카드의 유형 견본, BBVI·MCUI 막대, 조사량 견본

- 저장소: `gyunghun1214/blue-bio-map`, 최신 `main`에서 시작
- 작업 브랜치: 세션에 지정된 브랜치. 없으면 `ui/explore-dots-red`

## 이전 색 찾기 (값을 추측하지 않는다)

1. git 이력에서 점·버블이 청회색으로 바뀐 커밋을 찾는다.
   - 예: `git log -S '청회색' --oneline`, `git log --oneline -- dist/app.js dist/theme.css` 중 남색 지도 PR 병합 커밋
2. 그 커밋의 **바로 앞 커밋**에서 점과 버블의 색 값을 그대로 가져온다.
   - 점: `fill`, `stroke`, `opacity`(또는 `fillOpacity`), 반경은 바꾸지 않음
   - 버블: 채움·테두리 색, 셀당 기록 수 구간별 진하기 단계 값, 숫자 글자색
   - hover·선택 상태 색이 이전에 따로 있었다면 그 값도
3. 이전과 지금의 진하기 단계 수가 다르면 **지금 단계 수와 구간은 그대로 두고** 이전 빨간 계열 값으로 단계를 채운다. 그렇게 한 사실을 README에 적는다.
4. 빨간색이 여러 번 바뀐 이력이 있으면 **청회색으로 바뀌기 바로 전** 값을 쓴다.
5. 찾은 값을 커밋 해시와 함께 README 표(요소 · 이전 빨간 값 · 지금 청회색 값 · 출처 파일:행)에 남긴다.

## 절대 바꾸지 않을 것

- 점의 위치(셀 안 도식 무늬 좌표), 육지 위 점 생략 규칙, 점 크기
- 버블 묶음 규칙, 크기(모인 셀 수), 숫자, 진하기 구간 경계
- '활용 × 보전' 셀 색(네 유형 색, `matrixTypeColour`), 유형 미산출 회색, 4° 셀 테두리
- 선택 종 노란 실선·hover 노란 점선 테두리, 조사량 회색 음영
- 배경 지도(위성·수심), 남색 지도 패널·헤더 디자인
- 다른 탭(`#compare`, `#method` 디자인), 첫 화면 지구, `expedition.html`, 멍이, `og.png`
- `scripts/`, `config/`, `dist/*.json`

## 문구

색이 바뀌면 '청회색 점', '청회색 버블' 문구가 화면과 맞지 않게 된다.

- 탐색 지도 범례와 '근거와 방법' 탭 '자료를 읽을 때'의 점·버블 줄에서 **'청회색'이라는 낱말만** 이전 커밋의 문구로 되돌린다(예: '붉은'). 이전 커밋에 있던 표현을 그대로 쓰고 새 문구를 만들지 않는다. 그 밖의 글자는 바꾸지 않는다.
- `og:image:alt`는 이미 '붉은 점'이라 그대로 둔다.
- `verification/`에서 `청회색`을 검색해 이 낱말을 읽는 검사를 찾고 **기대값을 고친다.** 지우거나 건너뛰지 않는다.
- '청회색'이 점·버블이 아닌 다른 요소를 가리키는 곳이 있으면 그곳은 고치지 않는다.

## 확인할 충돌

- 빨간 점·버블이 '활용 × 보전' 셀 색(특히 붉은·주황 계열 유형 색)과 **같은 화면에 함께 나오는지** 확인한다. 함께 나온다면 다른 색을 고치지 말고 캡처와 함께 PR에 적어 팀이 판단하게 한다.
- 위성·수심 배경 각각에서 점과 버블이 보이는지, 버블 숫자 글자가 읽히는지 본다(WCAG AA 4.5 이상, 대비 값을 README에 적는다).

## 캐시

- 고친 CSS·JS 파일마다 `index.html`의 `?v=` 해시를 LF로 맞춘 파일 내용 sha256 앞 10자로 다시 계산한다(README 53행 규칙, `test_client_outdated.mjs`). 새 파일을 만들지 않았다면 `dist/_headers`는 건드리지 않는다.

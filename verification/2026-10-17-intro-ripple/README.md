# 첫 화면 로딩: 큰 동심원 파문 (2026-10-17)

원형 스피너(점선 원·차오르는 호·도는 점) 대신, 뷰포트 전체를 덮는 짙은 남색 바다 로딩으로 바꿨다.
가운데 로고·“바다의 가능성, 근거에서부터.”·준비 단계 문구가 있고, 화면 아래에서 넓은 동심원 7겹이 퍼진다.
준비가 끝나면 0.36초 안에 파동이 지구본 테두리로 모였다가 사라지며 기존 첫 화면이 드러난다.

## 동작

| 항목 | 값 |
|---|---|
| 파동 | 타원 7겹, 생애 9초, 1.29초 간격. 중심 (0.5W, 1.22H), 가로 반지름 (0.56+1.04p)·max(W, 0.75H), 세로 반지름 (0.25+0.37p)·H, 투명도 0.55·sin(πp). 굴곡 최대 2.5px |
| 단계 문구 | 페이지를 준비하는 중 → 지도를 불러오는 중 → 해양생물 자료를 불러오는 중 → 해양생물 N종 자료를 불러왔어요 (N = published + candidates). 실패면 ‘첫 화면을 여는 중’ |
| 시간 | 최소 600ms. 준비 끝나면 바로 360ms 전환. 자료가 오지 않으면 6.64초에 전환을 시작해 7초에 끝남. 늦은 프레임·숨은 탭은 전환을 줄이거나 생략 |
| 전환 | 0–120ms 문구, 120–240ms 바다 배경과 파동이 지구본 테두리(`frame`)로, 240–360ms 파동이 사라짐. `cubic-bezier(.22,1,.36,1)` |
| 움직임 줄이기 | 파동이 멈춘 한 장면, 전환 없이 바로 첫 화면. 스위치는 기존 `.gate-motion` 하나를 로딩 위에 둠 |
| 접근성 | 로딩 중에는 첫 화면이 inert(스위치만 빼고), `.gate-loader` role=status, 파동 캔버스 aria-hidden |

`is-ready`는 전과 같이 “첫 화면을 쓸 수 있음”을 뜻한다(전환 중은 `is-revealing`). uicheck·offline_check·expedition_check가 이 클래스를 기다렸다가 Enter를 누르기 때문이다.

## 캡처 (`capture.mjs`)

`capture.mjs`는 크기마다 `1-loading`(자료 요청을 붙잡아 둠), `2-reveal-40`/`2-reveal-57`(캡처를 위해서만 전환을 6초로 늘린 장면), `3-after`와
`timeout-7s`, `failed-data`, `still-loading`, `switch-during-loading`을 PNG로 찍는다. 저장소에는 그중 일부만 두고, 지구본이 있는 장면은 JPEG로 줄였다.
결과는 `results.txt` (21/21). uicheck.mjs는 228 PASS / 4 FAIL(지도 타일 차단 때문에 main에서도 나는 환경 FAIL 4건).

## 첫 그림·LCP (`lcp.mjs`)

같은 headless Chromium, CPU 4배 느리게, 150ms·1.6Mbps, 실행 3번의 중간값.

| | main(350d643) | 이 변경 |
|---|---|---|
| 휴대폰 390 FCP = LCP | 2956 ms | 2988 ms |
| 데스크톱 1440 FCP = LCP | 3208 ms | 3288 ms |

두 경우 모두 LCP 요소는 첫 화면 제목(`.gate-title`의 span)이고 첫 그림과 같은 시각이다. 이 변경에서는 제목이 로딩 레이어 아래에 그려져 있다(Chrome은 가려진 요소도 LCP로 센다). 사람이 처음 보는 것은 같은 시각에 그려지는 로딩 문구다. Lighthouse 점수는 재지 않았다.

# 매트릭스 사분면 이름이 점·밀집 구간 버튼과 겹치는 문제 고치기 — Claude Code 작업 지침

## 배경

비교와 지표 탭 '활용 × 보전' 매트릭스(`#compare`)에서, 휴대폰(390px)일 때 **사분면 이름표가 점과 겹친다.**

- 왼쪽 위 '보전 지표 높음 / 보전 연구 우선 검토': 붉은 점 셋이 둘째 줄 글자 위에 얹혀 `보전 연구 우선 검토`가 읽히지 않는다.
- 왼쪽 아래 '두 지표 모두 낮음 / 기초조사 검토': 파란 점 둘이 `기초조사 검토` 끝을 덮는다.
- 오른쪽 아래 '활용 지표 높음': 밀집 구간 버튼 `7종`이 이름표 앞 색 점을 가린다.

사분면 이름표(`.quadrant strong` / `.quadrant span`)는 사분면 모서리에 고정되어 있고, 점은 값에 따라 놓인다. 화면이 좁아 점이 이름표 자리로 들어온다. 모바일 글자 크기 작업(`prompts/mobile-type-scale-claude-code.md`)으로 이름표가 커져 겹침이 더 심해졌을 수 있다.

이 작업은 **점 위치는 그대로 두고, 이름표가 점·밀집 구간 버튼을 피해 자리를 잡게 하는 것**이다.

- 저장소: `gyunghun1214/blue-bio-map`, 최신 `main`에서 시작
- 작업 브랜치: 세션에 지정된 브랜치. 없으면 `ui/matrix-quadrant-label-overlap`

## 먼저 확인할 것 (README에 적는다)

1. 사분면 이름표의 마크업·선택자, 배치 방식(CSS 절대 위치, `app.js` 계산 등)
2. 점(`.matrix-point`), 밀집 구간 버튼(`.matrix-cluster-btn`, 점선 묶음), 선택 종 이름('참굴' 같은 `.point-label`)을 그리는 함수와 그리는 순서(z-index)
3. 점 이름 겹침 회피 코드가 이미 있는지. 있으면 그 장치를 이름표에도 쓸 수 있는지
4. 겹치는 폭·쌍: 390·360·768·1100·1440px에서 이름표 사각형과 점·버튼 사각형이 교차하는 경우를 스크립트로 모아 표로 적는다(사분면 · 겹친 대상 · 겹친 px). 필터(해조류·패류 등)와 비교 기준(가중치)을 바꿨을 때도 모은다.

## 할 것

### 1. 이름표 자리 고르기 (겹침 회피)

이름표마다 **자기 사분면 안의 후보 자리 네 곳**(사분면의 네 모서리 안쪽)을 둔다. 점·밀집 구간 버튼·선택 종 이름·기준선 숫자와 **가장 적게 겹치는 자리**를 고른다.

- 기본 자리는 지금 자리다. 지금 자리가 겹치지 않으면 옮기지 않는다(PC 화면이 바뀌지 않게).
- 겹침 판정: 이름표 사각형(두 줄 전체) + 여유 6px과 점(지름 + 여유 4px)·버튼 사각형의 교차. 점 이름표를 숨기는 모바일 상태에서는 숨은 이름은 빼고 계산한다.
- 네 자리가 모두 겹치면, 그 사분면 이름표를 **두 줄 그대로 그래프 바깥 가장자리**로 옮긴다. 위 두 사분면은 그래프 위쪽(축 이름 `보전 시급성 MCUI ↑` 줄과 겹치지 않게), 아래 두 사분면은 x축 눈금 아래(`활용가치 BBVI →`와 겹치지 않게)다. 가로 위치는 그 사분면 폭 안에 둔다. 바깥 자리가 필요한 만큼만 매트릭스 패널 위·아래 여백을 늘리고, 그래프 높이(380px)와 점 위치는 바꾸지 않는다.
- **이름표의 어느 줄도 숨기거나 줄이지 않는다.** 첫 줄(색 점 + 사분면 이름)과 둘째 줄(예: `보전 연구 우선 검토`)은 늘 함께 보이고 함께 움직인다. 말줄임(`…`)도 쓰지 않는다.
- 다시 계산하는 때: 처음 그릴 때, 필터·검색·비교 기준·선택 종이 바뀔 때, 창 크기가 바뀔 때(디바운스 100ms 안팎), 점 이름이 보였다 숨었다 할 때. 점을 다시 그리는 기존 함수 끝에서 한 번 부르는 방식이면 된다.
- 계산은 렌더 뒤 `getBoundingClientRect()` 한 번 측정으로 끝낸다. 반복 배치(물리 시뮬레이션 등)는 쓰지 않는다.

### 2. 그리는 순서와 바탕

- 이름표는 점·버튼 **아래** 층에 둔다. 점을 누르는 동작이 이름표에 막히지 않게 이름표는 `pointer-events:none`이다.
- 이름표 글자 뒤에 아주 옅은 패널색 바탕(`--cs-panel` 70% 안팎, 반경 6px, 안쪽 여백 2px 6px)을 깐다. 회피가 덜 된 경우에도 격자선·점선 위에서 글자가 읽히게 하기 위해서다. 사분면 색 구분이 흐려지지 않게 바탕은 최소로 한다.

### 3. 밀집 구간 버튼 `7종`과 색 점

- 밀집 구간 버튼도 1번 판정의 장애물에 넣는다. 버튼 위치(점 묶음 근처)는 바꾸지 않는다.
- 이름표 앞의 색 점이 버튼에 가려지면 안 된다. 1번 결과 자리가 그것까지 피하는지 검사한다.

## 절대 바꾸지 않을 것

- **점 위치**(BBVI·MCUI 값에 따른 `left`/`top`), 점 크기·색, 기준선 50, 축 눈금·축 이름
- 사분면 이름표의 **문구와 색**, 사분면 배경색
- 밀집 구간 묶음 규칙과 버튼 위치·동작, 점을 눌러 종을 고르는 동작, 선택 종 이름표 동작
- 매트릭스 높이, 글자 크기(13px 이상 유지, 줄이지 않는다)
- 겹침이 없는 폭(특히 1440px)에서의 화면
- `scripts/`, `config/`, `dist/*.json`, 다른 탭, 첫 화면, `expedition.html`, 멍이

## 검사

1. 먼저 매트릭스에 묶인 검사를 찾는다. `verification/` 아래에서 `quadrant`, `matrix`, `point-label`, `cluster`, `보전 지표 높음`, `기초조사 검토`로 검색한다. 이름표 위치를 고정값으로 기대하는 검사가 있으면 **기대값을 고친다**(겹침 없음을 보도록). 지우거나 건너뛰지 않는다.
2. 새 검사를 더한다(Playwright/uicheck 방식).
   - 360·390·768·1100·1440px, 필터 '전체'·해조류·패류·어류·기타 각각에서, 보이는 사분면 이름표 사각형이 점·밀집 구간 버튼·선택 종 이름과 교차하지 않는다.
   - 같은 조건에서 각 이름표가 그래프 영역(또는 바깥 자리로 옮긴 경우 매트릭스 패널) 밖으로 넘치지 않는다.
   - 같은 조건에서 네 이름표의 두 줄이 모두 보인다(각 줄 요소의 크기가 0이 아니고, 잘리지 않음).
   - 점의 `left`/`top`이 전후로 같다(모든 폭·필터).
   - 1440px '전체'에서 이름표 위치가 전과 같다(원래 겹침이 없었다면).
   - 매트릭스 `textContent`가 전후로 같다.
   - 점을 누르면 지금처럼 종이 선택된다(이름표가 막지 않는다).
3. CI 전체(`verify.yml`의 `node verification/test_*.mjs`, `python scripts/build_expedition_stops.py --check`, `python -m unittest discover -s verification -p 'test_*.py'`)와 로컬 `verification/uicheck.mjs`를 돌린다.
4. 직접 확인한다.
   - iOS Safari·Android Chrome 실제 기기에서 네 사분면 이름표가 모두 읽힌다.
   - 종을 고르고 바꿀 때, 비교 기준을 바꿀 때 이름표가 깜빡이거나 튀지 않는다.
   - 가로 넘침이 없고 콘솔 오류가 없다.
5. `app.js`·CSS를 고쳤으므로 `index.html`의 `?v=` 해시를 다시 계산한다(README 53행 규칙, LF로 맞춘 파일 내용 sha256 앞 10자, `test_client_outdated.mjs`). 새 CSS 파일을 만들었다면 `dist/_headers` immutable 목록에도 넣는다.

## 단계 2. 카메라를 시안에 맞추기 (끝)

`fit_camera.py`(이 폴더)가 시안 `../첫화면_디자인시안.png`에서 직접 잰다. 결과는 `fit_camera.json`.

1. **구 테두리**: 글자가 테두리에 걸리는 행(225–475)과 헤더·하단 선을 뺀 행마다, 예상 테두리 ±60px 안에서 가장 센 어두움→밝음 경계를 찾아 154점. 원 맞추기(대수적 최소제곱, 잔차 상위 10% 버리고 다시) 결과 중심 (1259.5, 695.7) = (75.33% W, 73.93% H), 반지름 718.4 = 76.34% H, 잔차 중앙값 0.58px. 프롬프트 값(75%·71%·76%)·PR #177 값(75.9%·72.6%·77.4%)과 비슷하다.
2. **지점**: 시안을 3–4배로 키운 격자 이미지에서 눈으로 읽었다(아래 표 "시안"). 캄차카는 화면 밖이라 뺐고, 랴오둥반도 끝을 더했다(12점).
3. **카메라**: 수직 원근 `perspective(lon,lat,lon0,lat0,P)`의 `lon0, lat0, P`와 원(테두리 값의 ±2% 안)을 최소제곱으로 맞췄다. 격자(경도 125–155, 위도 0–35, P 1.3–5) 출발점마다 `scipy.optimize.least_squares`로 미세 조정.

**시안 지리가 하나의 구로 맞지 않는다.** 시안은 생성 이미지라, 처음 시도(원 고정, 모든 지점 같은 무게)에서는 한반도 22.7px·제주 31.9px·홋카이도 79.6px·사할린 91.7px가 남았다. 원을 자유롭게 풀면 테두리와 전혀 다른 원(반지름 533px, 중심 높이 400px)이 나와야 일본까지 맞는다. 일본은 실제보다 약 1.5배 북동쪽으로 넓게, 제주는 해안에서 실제의 약 2배 떨어져 그려져 있다. 그래서 한반도를 시안 자리에 두는 것을 우선했다. 손실은 soft L1(10px)로 두고, 15px 묶음(한반도·제주·산둥·대만)의 무게를 5배로 했다.

결과(`dist/vendor/globe-v2/camera.json`, `intro.js` `CAMERA`·`FRAME`):

- `lon0 = 136.823`, `lat0 = 20.345`, `P = 2.7122`(반지름 단위 거리), 지평선 각 68.4°. 프롬프트 예상(45–60°)보다 조금 멀다. 테두리 원을 지키면서 한반도·대만 간격을 맞추면 이 값이 나온다.
- 화면 배치(1672×941): 중심 (75.0% W, 72.46% H), 반지름 77.86% H. 테두리 측정값 대비 중심 x −0.4%, 중심 y −1.99%, 반지름 +1.99%로 **±2% 안(통과)**. 반지름은 반올림하면 +2.004%가 돼서 0.7786으로 내렸다.

12점 중 7점 통과. 실패 5점은 모두 시안이 실제 지리와 다른 곳이다. 제주는 해안에서 너무 멀고, 일본·사할린·하이난은 실제 위치에서 벗어나 있다. 실제 해안선을 이 카메라로 시안 위에 겹쳐 보면 한반도·황해·대만·중국 해안은 시안과 맞고, 일본은 시안보다 작고 한반도에 가깝다. 실제 지구를 그리는 이상 이 차이는 없앨 수 없다.

코드:

- `intro.js` 순수 함수: `perspective(lon,lat,lon0,lat0,P,toRim)`(단위 원, 지평선 `acos(1/P)`, 밖은 `null`, `toRim`이면 테두리로 밀어 붙임), `inversePerspective(x,y,lon0,lat0,P)`(Snyder 1987), `project(lon,lat,toRim)` = 이 카메라. `orthographic`과 `GLOBE_CENTER`는 지웠다.
- `globeFrame`은 `FRAME`(0.75·0.7246·0.7786) 값을 쓴다. 너비의 55%를 넘지 않는 규칙, 본문 피하기, 휴대폰 `band` 배치(한반도를 띠 가운데)는 그대로이고 투영만 바꿨다. `cardPlace`의 시안 오프셋은 새 카메라의 한반도 기준으로 다시 쟀다(오른쪽 207·아래 60, 카드 왼쪽 위 1323,455). 크기 비율은 R/733.

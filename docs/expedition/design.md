# 바다 탐험 첫 버전 설계 (2026-10-08)

## 그래픽 기술: Three.js r170 (WebGL)

- 바다 셰이더·저폴리 배·항적 리본·카메라 추적을 직접 짠 WebGL로 만들면 행렬·메시 코드가 수백 줄 늘어난다. Three.js 하나로 줄인다.
- `dist/vendor/three-r170/three.module.min.js`(npm `three@0.170.0`, MIT, 692 KB, 압축 전송 약 170 KB)를 고정 버전으로 둔다. CDN·빌드 도구 없음. 출처·해시는 `dist/vendor/three-r170/SOURCE.txt`.
- 첫 로딩: 화면은 HTML 카드 목록을 먼저 그리고, Three.js는 `import()`로 뒤에 불러온다. 불러오기·WebGL 생성이 실패하면 카드 목록이 그대로 남는다(데이터 접근이 막히지 않음).
- 기존 지도 화면(`index.html`)은 Three.js를 불러오지 않는다.

## 파일 분리

- 새 화면: `dist/expedition.html` + `expedition.js` + `expedition.css` (`?v=` 해시, `_headers` immutable).
- 데이터: `scripts/build_expedition_stops.py` → `dist/expedition-stops.json`. 값은 `assessments.json`·`matrix-readiness.json`·`live-snapshot.json`·`cell-sea-areas.json`에서 복사만 하고, `--check`가 원본과 같은지 검사한다.
- 기존 화면 변경은 `index.html` 헤더의 '바다 탐험' 링크와 `theme.css`의 링크 모양뿐이다. `app.js`는 건드리지 않는다(열린 PR #152와 충돌 최소화).

## 탐사 지점 3곳 (운영 8종 중 매트릭스 유형이 서로 다른 3종)

| 순서 | 종 | 유형(`matrix-readiness.json`) | 고른 이유 |
|---|---|---|---|
| 1 | 참굴 *Magallana gigas* | 지속가능 활용 후보 | BBVI 83.9로 운영 8종 중 가장 높음. 식량(MFPI 71.6)과 생리활성(MBPI 96.3)이 함께 큰 종. MCUI는 한국 국가 평가 LC 10 |
| 2 | 미역 *Undaria pinnatifida* | 대체생산·배양 연구 | BBVI 71.0과 MCUI 80이 함께 높음. 단 MCUI는 연해주 지방 목록 참고값(역검증 미통과) 라벨을 같이 보여야 하는 종 |
| 3 | 해삼 *Apostichopus japonicus* | 보전 우선·모니터링 | IUCN 위기(EN, 2025 평가)로 MCUI 80. BBVI 36.1은 '단일 논문'. 민감종이라 4° 셀만 공개 |

- 세 종 모두 공개 관측 셀·네 지표·원문 링크가 있다. 톳(대체생산)·살오징어(지속가능)도 조건을 맞지만, 유형이 겹치지 않으면서 식량·생리활성·보전 대비가 가장 뚜렷한 조합을 골랐다.
- 지점 위치: 그 종의 공개 셀 중 한국 시험 범위(124–132°E · 33–38.7°N) 안이고 **셀 중심이 바다인** 셀 가운데 기록 수가 가장 많은 셀의 중심(빌드 스크립트가 `countries.json`으로 판정). 셀 칸(1° 또는 4°)을 바다 위에 그대로 그린다. 정확한 좌표는 만들지 않는다.
- 순서는 서해 → 남해 → 동해로 한 번에 도는 항로가 되게 셀 위치로 정했다. 지점 사이 경유점은 육지를 피하려고 넣은 **연출 값**이며 `expedition.js`에 따로 두고 화면에 "연출용 항로 · 실제 조사 항로나 선박 위치가 아님"을 항상 표시한다.

## 단일 탐색 상태

```
state = { stop: 0..2 (목표 지점), t: 항로 위 현재 위치(0..1), phase: 'intro'|'sailing'|'arrived',
          reveal: {지점별 0..4}, detailOpen, view: '3d'|'cards' }
```

- 입력(휠·스와이프·←/→·버튼·지점 목록·해시)은 `go(stop)` 하나만 부른다. 목표 지점만 바뀌고, 렌더 루프가 `t`를 목표 `t`로 최대 속도 제한과 감속으로 다가가게 한다. 빠른 연속 입력이면 마지막 목표로 곧장 간다.
- 배 위치·방향, 카메라, 정보 카드는 모두 같은 `t`·`stop`에서 계산한다. 카드 내용은 '도착한 지점'의 것만 보인다.
- 도착하면 `reveal`이 1 → 2 → 3으로 차례로 오른다(해역·기록 → 생물 → 핵심 가치). '자세히 보기'를 열면 4. 다시 찾은 지점은 이미 오른 단계부터 보인다.
- 상세 패널이 열려 있거나 도착 상태이면 배는 스스로 움직이지 않는다(자동 진행 없음). 패널이 열린 동안 휠은 패널 안에서만 쓰인다.
- URL 해시 `#stop=2`(1부터)로 지점을 남겨 새로고침·뒤로 가기가 같은 지점을 연다. 지도 화면에서 돌아올 때를 위해 마지막 지점은 `sessionStorage`에도 둔다.

## 화면 원칙

- 색: 짙은 네이비 바다, 흰 글자, 청록 라벨, 주황 포인트 소량. 글꼴 Pretendard.
- 문구: 관측 기록은 "이 셀에서 ○년 ○건 기록"으로만 쓰고 서식 여부를 말하지 않는다. MBPI·BBVI는 기존 화면의 라벨("보고된 화합물의 공개 생리활성(잠재력) · 종 추출물의 효능 아님", "종 전체 값 · 해역 값 아님", 축별 검증 결과)을 함께 둔다.
- 종 사진은 저장소에 없고 라이선스 확인을 이번 범위에서 하지 않으므로, 코드로 그린 SVG 일러스트 + "사진 자료 없음"으로 둔다.
- 오디오 없음.

## 대체 경로

- WebGL 실패·Three.js 로딩 실패: 카드 목록 화면(정적 바다 배경)으로 바꾸고 이유를 한 줄 알린다.
- 저성능(4초 평균 18 fps 미만): 픽셀 비율을 1로 낮추고 '카드 목록'을 한 번 안내한다. 자동으로 바꾸지 않는다(바쁜 순간의 일시적 저하로 화면이 바뀌면 혼란스럽기 때문).
- `prefers-reduced-motion`: 배는 지점 사이를 즉시 옮기고 물결·흔들림을 멈춘다. 등장도 즉시.
- '카드 목록으로 보기' 버튼은 3D 화면에서도 늘 있다.
